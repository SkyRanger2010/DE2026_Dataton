# Партиционирование Iceberg

Стратегия партиционирования таблиц хранилища (датаинженер Iceberg). Все партиции — по дате для эффективного среза по времени и удаления старых данных.

## Таблицы и партиции

| Схема / таблица | Партиция | Тип | Обоснование |
|-----------------|----------|-----|-------------|
| **raw.banner_events** | `event_date` | date | Срезы по дню, удобно для инкрементальной загрузки и TTL (например, горячее 30 дней). |
| **ods.banner_events** | `event_date` | date | Совпадение с raw для упрощения ETL и переноса партиций. |
| **dm.campaign_daily** | `date` | date | Агрегаты по дню; запросы BI всегда по дате/периоду. |
| **ml.user_features** | `snapshot_date` | date | Один срез признаков на дату; пересчёт по дням. |
| **ml.click_predictions** | `snapshot_date` | date | Результаты инференса по дате среза. |

## Формат партиции

- **Iceberg:** партиция задаётся при создании таблицы (`partitionedBy(col("event_date"))` в Spark, `partitioning = ARRAY['event_date']` в Trino).
- Все партиционные колонки имеют тип **DATE**; время хранится в отдельной колонке (event_ts и т.д.).

## Горячее / холодное хранение (архитектура)

- **Горячее:** последние 30 дней в Iceberg (быстрые запросы).
- **Холодное:** старые партиции можно переносить в отдельный бакет/кластер или удалять по политике TTL (через удаление партиций или `expire_snapshots` + `remove_orphan_files`).

См. [maintenance.md](maintenance.md) для операций по снимкам и файлам.
