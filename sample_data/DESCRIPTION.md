# Практический кейс: построение инфраструктуры хранилища данных

**Стек студента:** Hadoop, Spark, Trino, Iceberg, Kafka, ETL, Airflow, нормализация данных, ML, BI.

---

## Контекст

В крупной телеком-компании отсутствует реализация единой системы хранения данных. Данные разбиты локально по разным БД (данные по клиентам в PostgreSQL, данные по звонкам в ClickHouse, отсутствует интеграция с Яндекс.Метрикой для забора логов и т.д.).

Команде предоставляются следующие наборы данных в формате CSV:

| Набор | Файл | Поля |
|-------|------|------|
| Логи показов и кликов по баннерам | **Fct_banners_show** | banner_id, campaign_id, user_id, timestamp, placement (сайт/приложение/соцсеть), device_type, os, geo, is_clicked (0/1) |
| Данные об установках приложения | **Installs** | user_id, install_timestamp, source (баннер/органика/другое) |
| Данные о поведении пользователей после установки | **Fct_actions** | user_id, session_start, actions (регистрация, первый заказ и т.д.) |
| Метаданные по баннерам | **CD_banner** | banner_id, creative_type (статика/видео/анимация), message (сообщение на баннере), size, target_audience_segment |
| Бюджет и ставки по кампаниям | **CD_campaign** | campaign_id, daily_budget, **cpm/cpc (эту метрику студентам нужно высчитать самостоятельно)**, start_date, end_date |
| Данные о пользователях | **CD_user** | User_id, segment, tariff, date_create, date_end |

---

## Цели и задачи

Необходимо разработать инфраструктуру для написания ML-моделей и реализации BI в единой архитектуре платформы данных. При этом нет возможности проводить аналитику и строить модели и BI, поскольку данные разрозненно хранятся. Предлагается реализовать архитектуру хранилища данных с описанием ETL-пайплайнов загрузки и предложить вариант реализации BI-инструментов и ML-модели.

- **Проблема:** Отсутствует возможность строить модели и аналитику ввиду разрозненного хранения данных.
- **Задача:** Предложить варианты реализации хранилища данных и разработать пайплайн реализации ML-модели / BI-дашборда.

---

## Пример: диагностика и вопросы по архитектуре

- **Какие основные сущности можно выделить?** (клиент, звонок, услуги, выручка)
- **Вопросы, которые нужно задавать в процессе построения архитектуры:**
  - Какие данные требуют горячего/холодного хранения
  - Как реализовать забор данных (с помощью каких пайплайнов, фреймворков и т.д.)
  - Где и как хранить, что пойдёт в дашборды, модели
  - Масштабируемость системы (на случай новых интеграций с партнёрами или включения новых сервисов)
- **Пример модели на основе приведённых данных:** в контексте хранилища реализовать поток данных от источников к ML-модели, основываясь на предоставленных данных.

## Требования к задаче, инструменты, фреймворки

1. Описаны фреймворки для работы с данными (дано обоснование, почему выбран именно этот фрейм и какие варианты ещё могли быть).
2. Описаны БД и места хранения данных.
3. Учтена масштабируемость, кол-во запросов в секунду и т.д.

Основная задача — наличие обоснованных аргументов для защиты своих решений.

---

## Кейс выполнен, если:

- Описаны фреймворки и сущности для работы с данными.
- Описаны базы и формат хранения данных.
- Приведено обоснование и допущения, в рамках которых данное решение работает.
- Приведены реальные кейсы реализации потоков загрузки данных и реализации моделей и BI.
